## Highlights

> Novel Engine now has a complete Query Manager: a full submission-target tracker with AI-powered research, per-field auto-fill, and personalized query letter generation — all driven by the new Quill agent and integrated into the pipeline as phase 15. Web search is now available to every model provider (Claude, Ollama, llama-server, Codex), so agents can research agents and publishers regardless of backend. Codex CLI reliability has been substantially hardened: silent exits surface real errors, the 0.27.0 event envelope is parsed correctly, and transient stream failures retry automatically.

---

## Features

- **Query Manager** — A complete submission management system: domain types and pipeline phase registration (`'query-agents'` as 15th phase), `QueryService` for tracker I/O and CRUD, 11 IPC channels under `query:*`, `queryStore` Zustand store, a 5-component `QueryManager/` UI (QueryManagerView, TargetCard, AddTargetForm, LetterPreview, FilterBar), IconRail entry, PipelineSpine integration with phase detection, and Quill agent prompt with Phase 6 (personalized query letter generation). (#4d8e36e, #869e18d, #7c2bfe5, #89713d8, #20f3045, #c94a9b5, #64b19b0, #52aeea0)
- **WebSearch for all providers** — Cross-provider web search parity: new `WebSearcher` executor for Ollama/llama-server (DuckDuckGo HTML, no API key), `WebSearch` tool added to `OLLAMA_TOOLS`, Codex CLI `web_search` event recognition, `--enable standalone_web_search` flag on every Codex spawn, and `'query'` added to `StreamEventSource`. Query Manager streaming now broadcasts to the CLI Activity panel. (#2da43a3, #019fba4, #20b55e3)
- **Query auto-populate and per-field AI fill** — Quill can research and auto-populate submission targets in bulk using web search, and any individual field can be AI-filled on demand. New `ResearchPanel` component, `researchTargets()` and `fillTargetField()` on `QueryService`, two new IPC channels (`query:researchTargets`, `query:fillTargetField`), and Quill Phase 7 prompt for target research and field fill. (#3fa6475, #6087ffc, #bcdcd94, #3b57bb7, #756a4a0)

## Improvements

- **Query research failure handling** — Error `result` events from Claude CLI are now treated as errors (not silent completions), per-call `maxTurns` override gives research 40 turns, post-stream extraction guards against non-document content, and research failures/results surface in the Query Manager UI. (#c58ae8e, #58eae17, #ff6fa9a, #27b8bc3)
- **Query tracker parse resilience** — Lenient tracker parsing with content markers, hardened research and field-fill prompts, reliable `filesTouched` tracking in Claude CLI client, and a clobber guard to prevent tracker overwrites. (#408d8c8, #f8f1652, #3bf4f70, #ddcf377)
- **Query Manager activity in CLI panel** — All Query Manager streaming (research, generate letter, fill field) now broadcasts to the CLI Activity panel via `chat:streamEvent`, so users can monitor Quill's CLI calls alongside all other agent activity. (#019fba4)

## Bug Fixes

- **Codex silent exits surface as errors** — Codex runs that close without assistant text or usage are now treated as failures instead of successful empty responses. Bounded stdout/stderr diagnostics captured, native Codex error JSON forwarded as stream errors. (#cadbb1a, #02819b4)
- **Codex final-output fallback** — `--output-last-message` flag passed to `codex exec`; temporary final-message file read when JSON stdout closes without assistant text. Recovers text that would otherwise be lost. (#bfc313c, #02819b4)
- **Codex tool and file event tracking** — Completed Codex tool/file JSON items converted to stream activity; `file_change` events update `filesTouched` and emit terminal `filesChanged`, preventing false no-file pipeline runs. (#bfc313c)
- **Codex file-only success detection** — Clean Codex exits that update files but emit no assistant text are now classified as successful file-only completions via workspace snapshot diff, instead of surfacing a false error. (#6849254)
- **Codex unknown-event diagnostics** — Unknown Codex JSON event shapes now include compact key-shape summaries and bounded `unknownJsonTail` in exit diagnostics, making parser misses actionable. (#6849254)
- **Provider model resolution guardrails** — Stale model settings now resolve to an available provider model before chat streaming. Startup repairs stale `settings.json` model/provider pairs, ChatService records the effective model, and Settings shows a warning when the saved primary model is unavailable. (#614b47c)
- **Codex 0.27.0 envelope unwrapping** — Codex 0.27.0's `{"id":"0","msg":{...}}` event envelope is now parsed correctly. Assistant text, status, and usage extracted from nested envelope candidates instead of top-level keys only, so 0.27.0 text streams incrementally. (#426c4b4)
- **Codex real error surfacing** — Transient `stream_error` events (CLI retries internally) are distinguished from terminal `error` events. Terminal errors now report `Codex CLI reported an error: <real reason>` instead of a generic no-output diagnostic dump. (#5380110)
- **Codex bounded stream-failure retry** — Fully-empty transient Codex stream failures now automatically retry up to 2 times with linear 2s/4s backoff. Exactly one terminal `error` StreamEvent emitted when the run gives up. Stop during backoff cancels the pending re-spawn. (#a370e30)

## Upgrade Notes

No special upgrade steps required. There are no database schema migrations and no renamed IPC channels in this release.

1. Pull the latest `main`.
2. Run `npm install` (no new dependencies).
3. Rebuild and launch (`npm start` or `npm run build`).
4. Existing `settings.json` files are upgraded in place — stale model/provider pairs are repaired on startup.
5. The Query Manager is accessible via the mail icon in the IconRail (requires an active book with `publish` phase complete).
